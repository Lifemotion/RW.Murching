# Bwl.Murching

Локальные субтитры, перевод субтитров и переозвучка (даббинг) для аудио и видео. C# / .NET 10, пока только Windows. Ничего не уходит в облако: распознавание делает whisper.cpp на вашей видеокарте (или процессоре), переводит локальная LLM через Ollama, голос синтезирует XTTS-v2 на той же карте, звук извлекает и склеивает ffmpeg.

```
murch subs lecture.mp4                    # -> lecture.ru.srt, язык определяется сам
murch subs talk.mkv -f srt,vtt --json     # несколько форматов + транскрипт со словами
murch subs film.mp4 --embed               # субтитры внутрь копии видео: film.subbed.mp4
murch subs talk.mp4 --translate ru --bilingual   # + перевод на русский локальной LLM (Ollama)
murch translate talk.en.srt --to ru               # перевести готовые субтитры
murch dub talk.mp4 --to ru                # переозвучить: распознать, перевести, синтезировать голосом оригинала, смикшировать
murch cues talk.ru.murch.json --max-line-length 37   # перевёрстка без повторного распознавания
murch probe film.mp4                      # потоки, длительность, кодеки
murch doctor                              # ffmpeg / GPU / CUDA / модели
murch setup                               # скачать ffmpeg, библиотеки CUDA и модели
```

Репозитории: <https://dev.rainwalker.ee/RainWalker/RW.Murching> (основной), зеркало <https://github.com/Lifemotion/RW.Murching>. Образцы даббинга на общедоступных роликах лежат в [релизах на GitHub](https://github.com/Lifemotion/RW.Murching/releases).

## 1. Установка

### 1.1 .NET 10 SDK

Нужен .NET SDK 10.0 (не только Runtime). Проверить:

```powershell
dotnet --list-sdks
# 10.0.xxx [C:\Program Files\dotnet\sdk]
```

Если строки с `10.0.` нет, поставить любым способом:

```powershell
winget install Microsoft.DotNet.SDK.10
```

или скачать инсталлятор с <https://dotnet.microsoft.com/download/dotnet/10.0> (раздел SDK, x64). После установки перезапустить терминал.

### 1.2 Получить исходники и собрать

```powershell
git clone https://dev.rainwalker.ee/RainWalker/RW.Murching.git
cd RW.Murching
dotnet build -c Release
```

Сборка забирает пакеты NuGet (Whisper.net с CUDA-рантаймом, System.CommandLine, Spectre.Console); первый раз это ~200 МБ.

Исполняемый файл после сборки:

```
src\Bwl.Murching.Cli\bin\Release\net10.0\win-x64\murch.exe
```

Удобно добавить эту папку в `PATH` или сделать алиас. Все команды ниже написаны как `murch ...`; если папка не в `PATH`, подставляйте полный путь либо запускайте через `dotnet run --project src\Bwl.Murching.Cli -- subs file.mp4`.

### 1.3 Внешние компоненты: одна команда

```powershell
murch setup
```

Команда скачивает всё, чего нет, в `%LOCALAPPDATA%\Bwl.Murching`:

| Что | Откуда | Размер | Зачем |
|-----|--------|--------|-------|
| ffmpeg + ffprobe (портативная сборка BtbN) | GitHub | ~100 МБ | декодирование любого аудио/видео, встраивание субтитров, микс дубляжа |
| `cudart64_13.dll`, `cublas64_13.dll`, `cublasLt64_13.dll` | NVIDIA redist | ~440 МБ | GPU-инференс whisper.cpp; пропускается, если нет драйвера NVIDIA |
| `ggml-large-v3-turbo.bin` | Hugging Face (ggerganov/whisper.cpp) | 1,6 ГБ | модель распознавания по умолчанию |
| `ggml-silero-v5.1.2.bin` | Hugging Face (ggml-org/whisper-vad) | 1 МБ | детектор речи |

Отдельные части: `murch setup --ffmpeg`, `murch setup --cuda`, `murch setup --models`, `murch setup --model small`.

Если ffmpeg уже стоит и есть в `PATH`, он будет использован. Свою папку с ffmpeg можно указать переменной `MURCH_FFMPEG_DIR`, с CUDA-библиотеками — `MURCH_CUDA_DIR`, корень для данных — `MURCH_HOME`.

Для перевода дополнительно нужен [Ollama](https://ollama.com) с моделью (`ollama pull qwen3.5:9b`), для даббинга — Python-окружение из `scripts\setup-tts.ps1` (см. 2.6). Субтитры работают без того и другого.

### 1.4 Проверка

```powershell
murch doctor
```

Ожидаемый результат на машине с NVIDIA:

```
ffmpeg               ok   N-126782-... C:\...\ffmpeg.exe
NVIDIA driver        ok   nvcuda.dll loads
CUDA 13 libraries    ok   C:\Users\...\Bwl.Murching\cuda
whisper.cpp runtime  ok   Cuda: WHISPER : CUDA : ARCHS = 750,800,860,...
Models               ok   large-v3-turbo, silero-v5.1.2
```

Если в строке `whisper.cpp runtime` стоит `Cpu`, а видеокарта NVIDIA есть, значит не найдены библиотеки CUDA: `murch setup --cuda`. Драйвер должен поддерживать CUDA 13 (ветка 580+; `nvidia-smi` показывает версию CUDA в правом верхнем углу).

Без видеокарты всё работает на процессоре, просто медленнее: `large-v3-turbo` идёт примерно в 2× реального времени на 12 ядрах, `small` — существенно быстрее. Даббинг на процессоре возможен (`--device cpu`), но XTTS считает в 5–15 раз медленнее реального времени.

## 2. Использование

### 2.1 Субтитры к файлу

```powershell
murch subs "C:\video\lecture.mp4"
```

Что происходит:

1. `ffprobe` читает контейнер, `ffmpeg` декодирует дорожку в 16 кГц моно.
2. Silero VAD находит речь и режет её на куски до 30 с.
3. Участки без «речи», но со звуком (пение, рэп поверх бита) тоже уходят в Whisper как сомнительные и проходят строгий фильтр.
4. Whisper определяет язык по самому длинному куску и распознаёт всё с пословными таймингами.
5. Фильтр убирает типовые галлюцинации («Субтитры сделал…», «Thanks for watching», зациклившиеся фразы).
6. Из слов собираются реплики: до 2 строк по 42 символа, до 7 с, разрывы по концам предложений и паузам, скорость чтения до 21 симв/с.
7. Файл пишется рядом с исходником: `lecture.ru.srt`.

Внизу печатается сводка: язык, движок (GPU/CPU), сколько речи и реплик, время работы и первые реплики для беглой проверки.

### 2.2 Полезные ключи `murch subs`

| Ключ | Назначение |
|------|------------|
| `-o путь` | файл (для одного формата) или папка для результатов |
| `-f srt,vtt,ass,txt` | форматы, можно несколько; `txt` — текст с таймкодами `[   0.00 ->    4.04]  реплика` |
| `-l ru` | зафиксировать язык вместо автоопределения |
| `-m small` | другая модель: `tiny`, `base`, `small`, `medium`, `large-v3`, `large-v3-turbo`, квантованные `*-q5_0`, `*-q8_0`, либо путь к своему `.bin` |
| `--translate ru` | перевод субтитров на указанный язык локальной LLM через Ollama (см. 2.5); пишет `<имя>.ru.srt` и т.д. |
| `--bilingual` | вместе с `--translate`: ещё файл `<имя>.<исх>-ru.srt`, где в каждой реплике оригинал и перевод |
| `--translator-model qwen3:14b`, `--glossary "имена, термины"` | модель Ollama и подсказки переводчику |
| `--whisper-translate -m large-v3` | перевод речи на английский силами самого Whisper (turbo-модели этот режим игнорируют) |
| `--json` | сохранить транскрипт со словами `<имя>.<язык>.murch.json` — вход для `murch cues`, `murch translate` и скриптов проверки качества |
| `--embed` | положить субтитры мягкой дорожкой в копию видео `<имя>.subbed.mp4/mkv` |
| `--from 1:30 --to 5:00` | обработать только фрагмент; тайминги остаются абсолютными |
| `--audio-stream 1` | выбрать дорожку, если их несколько |
| `--prompt "Кёртис, Хормуз"` | подсказка модели: имена, термины, стиль пунктуации |
| `--beam 1` | жадное декодирование, быстрее и чуть хуже |
| `--device cpu` | принудительно процессор |
| `--vad-threshold 0.35` | ловить тихую речь поверх музыки (по умолчанию 0.5) |
| `--no-music-fallback` | не трогать участки, которые VAD не признал речью |
| `--no-vad` | скормить Whisper весь файл целиком (для чистой речи не нужно) |
| `--max-line-length 37 --max-lines 2 --max-duration 6 --cps 17` | правила вёрстки |
| `-v`, `-vv` | подробный лог; `-vv` показывает каждый распознанный сегмент и решения фильтра |
| `-q` | без прогресс-баров, только итог |

### 2.3 Перевёрстка без повторного распознавания

Распознавание — самая долгая часть. Сохраните транскрипт один раз и играйте с вёрсткой мгновенно:

```powershell
murch subs film.mp4 --json
murch cues film.en.murch.json --max-line-length 37 --cps 17 -f srt,vtt
```

### 2.4 Пакетная обработка

PowerShell:

```powershell
Get-ChildItem C:\video\*.mp4 | ForEach-Object { murch subs $_.FullName -o C:\video\subs\ --json -q }
```

### 2.5 Перевод субтитров (Ollama)

Перевод делает локальная LLM через [Ollama](https://ollama.com): поставить Ollama, затем

```powershell
ollama pull qwen3.5:9b          # ~6,6 ГБ, модель по умолчанию; qwen3:14b точнее, но нужна карта на 12+ ГБ
murch subs talk.mp4 --translate ru --bilingual
murch translate talk.en.srt --to ru -f srt,txt          # уже готовые .srt/.vtt
murch translate talk.en.murch.json --to de --glossary "Kurtis = Кёртис; сохранять сленг"
```

Реплики переводятся пачками по 24 с контекстом предыдущих строк, модель обязана вернуть ровно столько же строк (структурированный JSON-ответ); при расхождении пачка переводится построчно, так что тайминги никогда не «съезжают». Результат: `<имя>.ru.srt`, `<имя>.ru.txt`, при `--bilingual` ещё `<имя>.en-ru.srt`. Whisper к этому моменту уже выгружен, поэтому LLM и распознавание не делят видеопамять. Файлы на целевом языке `murch translate` пропускает.

### 2.6 Даббинг (переозвучка)

```powershell
.\scripts\setup-tts.ps1                        # один раз: venv Python 3.10–3.12, torch CUDA 12.8, coqui-tts (XTTS-v2), ~5 ГБ
murch dub talk.mp4 --to ru                     # распознать -> перевести -> озвучить -> смикшировать -> talk.dub.ru.mp4
murch dub talk.mp4 --to ru --subs talk.ru.srt  # озвучить уже готовый (и, если надо, отредактированный) перевод
python scripts\dub-roundtrip.py talk.dub.ru.mp4 --subs talk.ru.srt   # контроль: распознать дубляж и сравнить с текстом
```

Как это работает:

1. Переведённые реплики склеиваются в высказывания: незаконченное предложение всегда целиком, законченные соседние — если пауза между ними меньше 0,2 с; одно высказывание не длиннее 14 с.
2. Для каждого высказывания из оригинальной дорожки вырезается референс голоса — тот же говорящий в тот же момент (окно ≥ 6 с). Клонируется не «усреднённый» голос, а голос с настроением конкретной сцены; разные спикеры в разных сценах получаются сами собой.
3. XTTS-v2 синтезирует реплику этим голосом. Если она длиннее своего слота, сначала повторный синтез с ускоренным темпом речи (до ×1,3), потом `atempo` без изменения высоты (до ×1,35 суммарно); остаток уходит в паузу перед следующей репликой. Следующая реплика сдвигается не более чем на 0,8 с, чтобы задержка не накапливалась.
4. Реплики раскладываются на таймлайн, громкость подгоняется под RMS оригинальной речи в том же месте, оригинал под дубляжом приглушается (`--duck 0.2`, плавные края 250 мс), сумма мягко лимитируется.
5. `ffmpeg` подклеивает новую дорожку к видео без перекодирования картинки; оригинальная дорожка остаётся второй (`--no-original-track` убирает). Рядом ложится `<имя>.dub.json`: высказывания, длительности синтеза, темп, переполнения.

| Ключ `murch dub` | Назначение |
|------------------|------------|
| `--to ru` | язык дубляжа (обязателен) |
| `--subs talk.ru.srt` | готовый перевод; без него сначала выполняются `subs` + `translate` |
| `-o out.mp4` | имя результата (по умолчанию `<имя>.dub.<язык>.<контейнер>`) |
| `--engine xtts \| chatterbox` | движок TTS (см. ниже) |
| `--device cuda \| cpu` | где считать TTS |
| `--python путь\python.exe` | интерпретатор TTS-окружения, если оно не в `tools\tts-venv` (или переменная `MURCH_TTS_PYTHON`) |
| `--duck 0.2` | громкость оригинала под дубляжом (0..1) |
| `--voice-gain 1.0` | громкость дубляжа относительно оригинальной речи |
| `--max-speedup 1.35` | потолок ускорения при подгонке под слот |
| `--no-original-track` | не сохранять оригинальную дорожку второй |
| `--work-dir папка` | сохранить промежуточные WAV (референсы, синтез, микс) |

Модели TTS работают на PyTorch, поэтому живут в отдельном Python-окружении и вызываются как долгоживущий процесс `scripts/tts_worker.py` (JSON по stdin/stdout); .NET-часть делает планирование, подгонку, микс и mux. Движки: `--engine xtts` — XTTS-v2 (17 языков, включая русский; лицензия Coqui CPML — некоммерческое использование), `--engine chatterbox` — Resemble Chatterbox Multilingual (MIT; ставится `setup-tts.ps1 -Chatterbox`). Веса XTTS (~1,9 ГБ) скачиваются при первом запуске в `%LOCALAPPDATA%\tts`. Требования: Python 3.10–3.12 (3.14 не поддерживается torch), ~3 ГБ видеопамяти под XTTS; пины пакетов (torch 2.8, transformers 4.x, spaCy) зашиты в скрипт установки.

Что показали первые прогоны (клип диалога 60 с, английский → русский, RTX 3060):

| Вариант | Высказываний | Темп | Переполнений | Дрейф | WER обратного распознавания |
|---------|--------------|------|--------------|-------|------------------------------|
| склейка близких реплик (по умолчанию) | 5 | ×1,0–1,16 | 0 | 0,3 с | 6–10% |
| каждое предложение отдельно | 12 | до ×1,35 | 4 | 34 с | 18% |

Русская речь примерно на 20% длиннее английской при том же темпе, поэтому короткие слоты быстрого диалога заполнить не удаётся, а длинные высказывания ложатся хорошо. Обратная сторона склейки: в быстром диалоге двух персонажей одно высказывание может содержать обе реплики, и референс голоса окажется смешанным. Полная обработка минуты видео занимает около полутора минут (два прохода синтеза).

## 3. Как это устроено

```
ffmpeg ──► 16 kHz mono PCM ──► Silero VAD ──► речевые чанки (≤30 с) ──┐
        │                          │                                   ├──► whisper.cpp (CUDA) ──► сегменты + токены (DTW)
        └── ffprobe                └── энергичные «не-речевые» участки ─┘          │
                                       (сомнительные, строгий фильтр)              ▼
                                                                          слова ──► фильтр галлюцинаций
                                                                                   ▼
                                                                          построитель реплик (ДП по предложениям,
                                                                          паузам, 42×2, ≤7 с, ≤21 симв/с)
                                                                                   ▼
                                                    .srt / .vtt / .ass / .txt / .murch.json ──► Ollama (перевод) ──► .ru.srt
                                                                                                                       ▼
                                                        видео ◄── ffmpeg mux ◄── микс с приглушением ◄── XTTS-v2 (сайдкар) ◄── высказывания + референсы
```

* **ASR**: [Whisper.net](https://github.com/sandrohanea/whisper.net) (whisper.cpp), модель `large-v3-turbo` GGML; сборка CUDA 13 для NVIDIA, откат на CPU.
* **VAD**: Silero v5 через whisper.cpp — модель видит только речь, длинные тишины не доходят до декодера.
* **Музыкальный фолбэк**: Silero не считает речью пение, рэп и вокодер. Промежутки длиннее 3 с с уровнем выше −40 dBFS распознаются как сомнительные: сначала определение языка по фрагменту (не совпал с языком файла — фрагмент выброшен), затем строгий фильтр (≥3 слова, средняя вероятность ≥0,75, без повторов и циклов n-грамм, без дежурных фраз вроде «I'm going to go»).
* **Пословные тайминги**: token timestamps + DTW-выравнивание по attention-головам модели; слова собираются из байтовых BPE-токенов, а текст берётся из сегмента (кириллица не ломается).
* **Реплики**: минимизация стоимости разбиения — концы предложений, запятые, паузы, штрафы за короткие реплики и за перенос строки после предлога/союза; время показа растягивается под скорость чтения, между репликами минимум 80 мс.
* **Перевод**: Ollama chat API со схемой JSON-ответа, пачки по 24 реплики со скользящим контекстом, построчный откат при несовпадении числа строк.
* **Даббинг**: планировщик высказываний, референс голоса из оригинала, TTS-сайдкар, подгонка темпа (повторный синтез, затем `atempo`), микс с приглушением в памяти, mux без перекодирования видео.

### Проверка качества

* `scripts/verify-elevenlabs.py` отправляет звук в ElevenLabs Scribe, кэширует ответ как `<имя>.eleven.json` и печатает WER и медианный сдвиг начала слов между двумя транскриптами (`$env:ELEVENLABS_API_KEY="..."` заранее; ключ в репозиторий не попадает). На наборе из 13 разношёрстных роликов чистая речь дала 2–3,5% WER при сдвиге ~70 мс; на песнях и рэпе поверх бита Whisper теряет строки (25–45%).
* `scripts/dub-roundtrip.py` распознаёт готовый дубляж тем же Whisper на целевом языке и сравнивает с озвученным текстом: низкий WER означает, что синтез разборчив и лежит по времени там, где субтитры.

## 5. Типичные проблемы

| Симптом | Причина и решение |
|---------|-------------------|
| `whisper.cpp runtime ... Cpu` при наличии NVIDIA | нет CUDA-библиотек: `murch setup --cuda`; либо старый драйвер (нужна поддержка CUDA 13) |
| `ffmpeg/ffprobe were not found` | `murch setup --ffmpeg` или поставить ffmpeg и добавить в `PATH` |
| `--whisper-translate` оставил исходный язык | модель `*-turbo` не переводит; `-m large-v3` или `-m medium`, либо `--translate en` через Ollama |
| `Ollama model ... is not available` | запустить Ollama (`ollama serve` или приложение) и `ollama pull qwen3.5:9b` |
| `TTS environment not found` | выполнить `scripts\setup-tts.ps1` или указать `--python` / `MURCH_TTS_PYTHON` |
| `TTS worker exited during start-up` | запустить с `-vv`, чтобы увидеть трассировку Python; чаще всего это версии пакетов: coqui-tts 0.27 требует `transformers<5`, torch 2.9+ требует torchcodec с DLL FFmpeg (скрипт ставит torch 2.8), длинные фразы требуют `spacy` |
| `CUDA out of memory` при даббинге | выгрузить модель Ollama (`ollama stop qwen3.5:9b`) или запустить TTS на процессоре `--device cpu` |
| Дубляж не помещается, много «OVERRUN» | перевод длиннее оригинала: поднять `--max-speedup`, сократить перевод в `.ru.srt` и перезапустить с `--subs`, либо взять более лаконичную модель-переводчик |
| Пропущены строки песни / рэпа | понизить `--vad-threshold 0.35`; проверить, что не указан `--no-music-fallback` |
| Странные фразы в тишине или на музыке | это галлюцинации Whisper; `-vv` покажет, что отфильтровано |
| Медленно | проверить `murch doctor` (GPU или CPU), взять `--beam 1` или модель поменьше |
